## Phase 1 — Fix the broken AI contract (P0; makes the app actually work)
The API route was rewritten to only handle `validate_key` / `fetch_models` / `run_playground`. `triggerExecutiveAudit` sends **no action**, so every audit 400s silently.

- **`app/api/ai/health-scan/route.ts`** — full rewrite:
  - Restore `run_audit` action (calls `runPulseAIGovernorScan`).
  - Normalize request shape (settings page currently sends `{validateOnly, apiKey}` — wrong; standardize on `{action, providerType, userApiKey, ...}`).
  - Require explicit `action`; `400` for unknown/missing instead of falling through to a fake audit (6.4).
  - Empty-prompt guard on playground/chat → `400` (6.9).
  - **Fix cache poisoning (6.3):** replace the module-singleton cache with a composite-key (`hash(payload + provider + model + mode)`) Map + TTL, bounded. No more demo result served for a real-key call.
  - Friendly error mapping (6.7, 6.8): 429/quota → "Rate limit reached — retry in ~Ns or switch models"; 400 → "API key rejected"; 403 → "key lacks access". Return a structured `error` field, never stuff raw provider RPC into `response`.
  - Route audit + chat through `providers.ts` (all 4 providers), not the Gemini-only SDK.
  - Return `{ usage, estimatedCostInr, latencyMs }` in every real response so the store can track spend.
- **`lib/store/usePulseStore.ts` → `triggerExecutiveAudit`:** add `action: "run_audit"`; write `today_ai_cost_inr`, `budget_used_inr`, `avg_latency_ms`, token totals from response; surface `last_error`.
